# v1.8.0 brief

**Requested:** "go ahead with items 1-5 and 8" — from the peer-session security review relayed earlier (items 6–7 deliberately excluded: 6 is blocked pending a real custom domain, 7 requires manual dashboard verification the user would need to do themselves).

**Delivered:**

1. **Web3Forms key domain restriction** — cannot be done from this repo (it's a Web3Forms account/dashboard setting, not a code change). Documented clearly, with the exact steps, in both `README.md` and the new `SECURITY.md`, rather than silently skipped.
2. **`maxlength` on every contact-form field** — name/company 100, email 254, phone 20 (matches the existing `pattern`'s own `{7,20}` range), message 2000.
3. **Google Fonts GDPR concern — resolved by self-hosting**, not just "decided": fetched Google's own served CSS with a real browser User-Agent (to get `woff2` URLs rather than older fallback formats), identified that only 5 *unique* font files are actually needed (DM Sans and Playfair Display's normal weights are variable fonts serving multiple `font-weight` declarations from the same file — confirmed by file size and by cross-referencing which URLs repeated), downloaded them into `fonts/`, wrote matching `@font-face` rules in `styles.css`, and removed the Google Fonts `<link>` tags from `index.html`. Kept only the "latin" unicode-range subset — verified this doesn't regress anything, since it's the same subset an English-language visitor's browser would already receive from Google (confirmed the one glyph outside that subset used on the page, the ↗ arrow, isn't in Google's latin *or* latin-ext subsets either, so its rendering is unchanged either way). Simplified `_headers`' CSP (`style-src`/`font-src` → `'self'`) now that the external font origins are gone.
4. **Privacy notice** — expanded the existing one-line data-use note in the contact form's footer to name Web3Forms specifically (the third party that actually handles the submission) and link their privacy policy (verified the URL is real and loads correctly — a plain `curl` got a 403 from their bot protection, but the real browser tool confirmed the page title "Privacy Policy - Web3Forms" loads fine). Didn't build a full standalone privacy-policy page, since the form only collects data needed to answer a trade enquiry (not marketing/tracking data) — proportionate to what's actually being collected.
5. **EXIF/GPS stripping** — checked all 11 files in `assets/` (`magick identify -verbose <file> | grep -i "^  Profile"`, run individually on every file, not a sample) and found **zero** embedded metadata on any of them; they were already clean before this review. Rather than falsely claim to have "stripped" something that wasn't there, documented the check itself as a standing step in `README.md`'s "Product galleries" section, so the next photo added actually gets checked (the real risk was always about *future* photos, not the current ones).
8. **Future-payment PCI-DSS note** — added as `SECURITY.md`, not just a stray README line, since it's the kind of thing worth a dedicated, easy-to-find home; explains *why* a hosted checkout matters (keeps the site out of PCI-DSS scope entirely) rather than just stating the rule. Also used this file as the natural home for the account-level items (2FA, HSTS preload, the Web3Forms key restriction) that don't have a code fix. Linked from `README.md`; excluded from the public deploy via `.assetsignore`, matching the other internal docs.

**Verified end-to-end after all changes together** (not each item in isolation): loaded the site fresh, confirmed via `document.fonts` and the network request log that all 9 registered font-face declarations resolve to the 5 local files (not `fonts.gstatic.com`), confirmed computed `font-family` on real headings/body text shows the actual webfonts rather than a system-font fallback, ran a full live contact-form submission through Web3Forms with the new simplified CSP active (succeeded), confirmed `maxlength` values via the DOM on all six fields, and checked for console errors throughout (none).

**Released as:** v1.8.0 (minor — a genuinely new capability set: self-hosted font architecture, a new security-documentation file, plus form/privacy hardening, not just a bug fix, per `VERSIONING.md`).
