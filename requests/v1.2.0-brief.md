# v1.2.0 brief

**Requested:** Make all fields in the contact form mandatory, and add UI validation for the corresponding fields.

**Delivered:**
- `required` added to company, phone, and location inputs (name, email, message were already required).
- Discovered along the way: the form has `novalidate` (added in v1.0.0 so the site could fully own the error styling instead of relying on inconsistent native browser tooltips), which meant `required`/`type="email"` were never actually enforced before — the JS submit handler called `preventDefault()` and proceeded regardless of empty fields. This version adds the enforcement that was missing.
- Custom validation layer in `script.js`: each field is checked with the Constraint Validation API (`checkValidity`, `validity.valueMissing`/`typeMismatch`/`patternMismatch`) on blur and on submit, with a friendly message written into a dedicated error `<span>` under each field (`aria-describedby`-linked, `aria-live="polite"`).
- Phone field gets a `pattern` for a basic valid-characters check (digits, spaces, `+`, `-`, parentheses, 7–20 characters).
- "Product(s) of interest" now requires at least one checkbox — implemented via `setCustomValidity()` on the first checkbox in the group, since HTML `required` can't express "at least one of a group" for same-named checkboxes.
- `:user-invalid`/`:user-valid` CSS gives each field a coloured underline once the visitor has interacted with it (not on page load, avoiding a wall of red on an empty form).
- Submission is blocked, the first invalid field is focused, and a status message appears near the submit button until every field passes.

**Released as:** v1.2.0 (minor — new form-validation behaviour, per `VERSIONING.md`).
