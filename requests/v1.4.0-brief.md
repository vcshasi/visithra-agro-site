**Approach for #3/#4 (the big one):** every attempt this session at the gallery frame (v1.1.0's variable-width slide, v1.3.2's full-width-but-still-`contain` slide, v1.3.3's taller-frame-for-portraits, v1.3.5's viewport-capped frame, v1.3.6's revert) was built around `object-fit: contain` — showing the whole photo uncropped, which mathematically requires the frame's own aspect ratio to be tuned per photo orientation to avoid empty space, and that tuning kept conflicting with other goals (fitting the viewport, in particular). Given explicit permission to abandon that constraint, switched to `object-fit: cover` on a single fixed `aspect-ratio: 4/3` frame, applied identically to every photo in both galleries. This means every photo fills its frame completely (cropped as needed) with zero empty space, is unaffected by orientation, and needs no per-family or per-viewport tuning at all — which is also what shrank the frame (and so the whole card) down to a size that comfortably fits a normal browser window. Verified: every photo in both galleries loads (200 OK) and renders at the same 4:3 box; the product card is ~570-600px tall and fits fully inside a 1280×900 viewport with no scrolling.

**Delivered for the rest:**
1. Removed the `<p class="reveal">` from `.products-heading`.
2. `.products-heading` changed from a 3-column grid to a centered flex column (`align-items: center; text-align: center;`) with `gap` between the label and heading and `padding` above/below the block; `.products h2` set to `white-space: nowrap` (single line) above 760px, reverting to normal wrapping on mobile.
5. Added `<span class="required-mark" aria-hidden="true">*</span>` (rust-coloured) after every required field's label/legend text, and simplified the top-of-form note to "* Required field" to match. `aria-hidden` because the `required` attribute already announces this to screen readers — the mark is a purely visual convention.
6. Kept v1.3.6's centered pagination row below the card (this *is* "center" — nothing to revert there). Made the inner per-photo gallery-nav buttons smaller (34px → 30px) and translucent by default (full color/opacity only on hover/focus), so they read as a secondary, in-photo control rather than visually competing with the primary family-switcher row below.
