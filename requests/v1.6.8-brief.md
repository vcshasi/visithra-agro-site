# v1.6.8 brief

**Requested:** four screenshots from testing a very narrow browser window: (1) the Gloriosa tuber photo nearly edge-to-edge with barely any margin around it; (2) Coconut Products text clipped on the left ("...cts, carefully sourced and", etc.); (3) the mobile fullscreen menu with no visible way to close it and return to the page without picking a link, suggesting a close button in the top right; (4) a comparison showing the card's bottom-left corner correctly rounded, contrasted with a sharp/square-looking margin on the right side.

**Delivered:**
1–3 (margin, text clipping, sharp corner — all one root cause): traced to `.product-card`'s mobile rule, `min-width: 90vw`. That sizes against the full, raw viewport width, but the card lives inside `.products`, which already carries its own horizontal padding (`7vw` at this breakpoint) — so "90% of the viewport" was always more width than the card's container actually had left to give it. The card overflowed rightward to make up the difference, and the narrower the window, the worse it got: measured directly at 250px wide, the gap between the card and the screen edge was 17.5px on the left but only 7.1px on the right (and heading toward zero/negative below that) — which is exactly a shrinking margin, a corner with no room left to round, and, since the same overflowing card carries both the image and the text, clipped text too. Changed `min-width: 90vw` to `min-width: 90%`, which resolves against `.product-track`'s own width — already inside the section's padding — so the card can never need more room than it actually has, at any width.
4: `.menu-toggle` (the hamburger button, which turns into an "✕" once the menu is open via existing `[aria-expanded="true"]` styling) had `z-index: 2`, while `.site-menu`'s fullscreen overlay had `z-index: 15` — both are children of the same fixed-position header, so once the menu opened, its full-screen overlay visually sat on top of and completely hid the toggle button. It was technically still there and clickable, just invisible, which is exactly the problem described: no visible way to close the menu without choosing a nav item. Went with the user's own suggestion (a button in the top right that closes the view) since it was already the intended design — the close-state "✕" styling existed and just couldn't be seen. Raised `.menu-toggle` to `z-index: 16`.

**Verified:**
- Re-measured the card at 250px viewport width after the fix: no horizontal page overflow, and the outer margin no longer shrinks toward the right edge (confirmed via direct `getBoundingClientRect()` comparison, plus a visual screenshot showing intact rounded corners on all four sides of the card).
- Checked the Coconut card's paragraph and all four subproduct names at 250px width: none clipped (`scrollWidth === clientWidth` on the paragraph; all four subproduct names read back intact).
- Confirmed via `document.elementFromPoint()` at the toggle button's own screen position that it is now the topmost element while the menu is open (previously the overlay was) — visible, and a follow-up click correctly closes the menu (`aria-expanded` back to `false`, overlay slid off-screen). Took a screenshot of the open state showing a clear white "✕" in the top-right corner.
- Re-checked 375px width (no overflow, same non-overflowing margin behavior) to confirm the fix holds across the mobile range, not just the extreme case. No console errors.
