**Requested (in order, across one back-and-forth):**
1. "Here are the final images to include in website" — initially pointed at a WhatsApp-exported zip in Downloads.
2. "note that one product-group can have more than one image" — confirmed multi-photo galleries per family (already the design since v1.1.0).

4. "Maximize the photo frame if necessary" — the compact 4:3 gallery frame from v1.1.0 was cropping the new photos.
5. "donot limit it to a fixed frame. fixed frame idea was just temporary" — clarified #4: remove the fixed aspect-ratio entirely, not just resize it.

**Investigation:**
- The WhatsApp zip (`WhatsApp Unknown 2026-09-15 at 22.14.28.zip`) contained 12 raw photos; 3 were byte-identical to images already in use. A first pass added 7 of the remaining 9 to the site directly from that raw export.
- The `choosen photos` folder arrived shortly after and was clearly the authoritative, intentional set (professionally named, several with visibly reduced file sizes indicating real resolution/compression correction — one file, `gloriossa-superba-tuber-enhanced.png`, is a corrected replacement for the tuber photo already on the site, same filename, 2.7MB → 1.3MB). The 7 files added from the raw WhatsApp export were removed from `assets/` (moved to a scratch folder, not deleted) before this curated set was used instead.

**Delivered:**
- Copied the 8 files from `choosen photos/` into `assets/`: 5 new Gloriosa Superba photos + the resized tuber PNG replacing the old one in place, and 2 new Coconut photos.
- `productGalleries` in `script.js`: Gloriosa Superba's gallery grew from 3 to 8 photos, Coconut's from 1 to 3.
- Removed `aspect-ratio: 4/3` and `object-fit: cover` from the gallery frame (`styles.css`). The frame now has a flexible `height` (a `clamp()`, not a fixed ratio) and each photo is `object-fit: contain` at its own natural width — no cropping, whatever the photo's orientation.
- Rewrote the gallery's index-tracking and prev/next navigation in `script.js` to work by each slide's actual position (matching the pattern the outer product-family carousel already used), since the old logic assumed every photo was exactly one frame-width wide — no longer true once photos aren't force-cropped to a uniform box.
- Rebalanced `.product-card`'s grid from `.82fr 1.18fr` to `1fr 1fr` so the gallery has as much room as the text detail.

**Released as:** v1.3.0 (minor — real content plus a structural change to how the gallery frame works, per `VERSIONING.md`).
