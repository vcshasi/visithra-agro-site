# v1.9.0 brief

**Requested:**
1. "Mobile number — for India +91-9443311219, for Europe +49-15511371259"
2. "Include Icons like whatsapp and call (matching the website) to provide intention that the numbers are available for both"
3. Custom domain email via Zoho Mail — recommendation + walkthrough (handled separately; not part of this release, see below)

**Delivered (items 1–2):**
- `CONFIG.phones` in `script.js` replaces the single `phone` string with a list of `{ region, number }` entries — India and Europe, as given.
- Contact section renders one row per number: a region badge, the number as a `tel:` link, and two icon buttons — call (`tel:`) and WhatsApp (`https://wa.me/<digits>`, derived automatically from `number`).
- Icons are inline SVG, monochrome via `currentColor`, following the site's existing `--leaf`/`--rust` hover pattern rather than WhatsApp's brand green — matching the site's own restrained, typographic visual language (the site otherwise uses text glyphs like `→`/`‹`/`›` rather than an icon set, so "matching the website" was read as *palette and restraint*, not literal continuation of the glyph trick, since no existing glyph reads as "call" or "WhatsApp").

**Item 3 (custom email) — deliberately not part of this code release:** recommended Zoho Mail (free tier, custom domain, already the user's stated plan) and walked through the DNS/mailbox setup separately in chat, since it's an external dashboard flow with no MCP tool available for it in this session. `CONFIG.businessEmail` is intentionally **not** changed yet — switching it before the new mailbox is confirmed to actually receive mail would silently break real enquiries (contact form submissions and the "Email" link) by pointing them at an address nobody is checking. Will ship as its own version once the user confirms the Zoho mailbox is live and receiving mail.

**Verified:** local preview via a static file server, DOM/computed-style inspection (screenshots were unreliable this session due to a recurring test-harness rendering issue unrelated to this change) — both phone rows render with correct hrefs, digits-only WhatsApp numbers, descriptive `aria-label`s, correct region-badge and hover styling (including confirming CSS specificity resolves as intended against a pre-existing descendant-selector rule that would otherwise have overridden the badge), no console errors, no horizontal overflow at 375px mobile width, `deploy.sh --check-only` passes.

**Released as:** v1.9.0 (minor — new Contact-section feature, per `VERSIONING.md`).
