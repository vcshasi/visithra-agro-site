# v1.5.5 brief

**Requested:** "enable multiple browser support for the code so far. It should ideally support for all types of major browsers existing. Idea is to have the same design, features, functionalities across multiple browsers."

**Delivered:**
Audited `index.html`, `styles.css`, and `script.js` for features with incomplete or inconsistent support across Chrome, Firefox, Safari (desktop + iOS), and Edge. Most of the codebase was already within the safe baseline for current major browsers (`aspect-ratio`, `clamp()`/`min()`/`max()`, flexbox `gap`, CSS Grid, `:focus-visible`, `:user-invalid`/`:user-valid`, the Constraint Validation API, `fetch`/`AbortController`/`IntersectionObserver` in `script.js`). Four concrete risk points were found and fixed in `styles.css`, all via the "declare a safe fallback first, let the modern value override it in the cascade" pattern, so nothing changes for browsers that already support the modern feature:

1. `backdrop-filter` was unprefixed in four places (`.site-header`, `.carousel-button`, `.gallery-count`, `.gallery-nav`). Added `-webkit-backdrop-filter` alongside each, so the frosted-glass look also renders on Safari versions that require the prefix rather than silently showing a flat background.
2. `.hero { min-height: 100svh }` and `.gallery-stage { height: min(48vw, 55svh) }` use the `svh` unit — unsupported in older engines, where an unrecognised unit invalidates the *whole* declaration (not just that value), silently dropping the sizing entirely. Added a `100vh` / `min(48vw, 55vh)` declaration immediately before each `svh` one, so unsupporting browsers get a still-correct viewport-relative fallback instead of losing the property.
3. Added `-webkit-text-size-adjust`/`text-size-adjust: 100%` (prevents iOS Safari's automatic text-inflation on rotation) and `-webkit-tap-highlight-color: transparent` (removes the default grey tap flash on Android Chrome/iOS Safari for the site's custom-styled links and buttons), for visually consistent mobile behaviour.
4. Added `appearance: none` to the base `button` reset so buttons render from the site's own CSS everywhere, instead of each browser's native button chrome peeking through subtly.

**Verified:** re-measured `.gallery-stage` height, `.products`/`.contact` section heights, card padding, and computed `backdrop-filter` values at 700px, 816px, and mobile (375×812) viewport sizes after the change — identical to the v1.5.4 figures (e.g. 448.8px stage height at 816px, 51px margin at 700px), confirming the fallback declarations are inert in this (Chromium-based) test browser and only take effect where the modern feature is actually unsupported. No console errors, no horizontal overflow, buttons/backdrop-filter/text sizing all computed as expected.

**Released as:** v1.5.5 (patch — a compatibility/robustness correction with no visible or functional change on supporting browsers, per `VERSIONING.md`).
