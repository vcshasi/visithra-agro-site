# v1.3.4 brief

**Requested:**
1. "The gloriosa image still looks cluttered... I needed the image to look something like [the attached photo of the Coconut gallery, with the photo centered and visible space top and bottom]."
2. "The scroll button for the main-product scroll at the top right of the frame is not user friendly. How about keeping them on the sides... left and right of the complete product-group frame... If this is not possible make it compatible as to your choice."

**Investigation for #1:** re-verified the v1.3.3 CSS directly from the served file (`fetch('styles.css')` + regex match) and from `getComputedStyle` on the live page: `.gloriosa-card .gallery-stage` was already `height: clamp(340px, 64vw, 700px)` and rendering at 700px tall exactly as intended — the fix was correct. The attached reference photo was of the *Coconut* gallery (visible in its own caption/count badge), used as an example of the target look, not evidence Gloriosa was still broken. The most likely explanation: the throwaway local PowerShell preview server had no cache headers, so a plain browser reopen could have served a stale, pre-fix `styles.css`. Added `Cache-Control: no-store` to that server so this can't recur — no site-code change was needed for #1 itself.

**Delivered for #2:** Restructured the product-family carousel controls:
- `index.html`: the old `.product-controls` bar (prev button, "01/02", next button, all inline above the cards) is now a `.product-index-label` (just the "01/02" text, kept above the cards) plus a new `.product-carousel` wrapper around `#product-track`, with the prev/next `<button>`s as its direct children (siblings of the track, not nested inside it).
- `styles.css`: `.product-carousel { position: relative; }` with `.carousel-button-prev`/`.carousel-button-next` absolutely positioned at `top: 50%` (vertically centered) and `left`/`right: -.5rem` (`-.25rem` on mobile) — sitting just outside the card's edge, overlaid on the card's rounded corner. Buttons enlarged slightly (38px → 44px desktop) and restyled to sit legibly on top of either the dark gallery panel or the light detail panel, matching the existing translucent-blur treatment already used for the inner photo-gallery nav buttons.
- No JavaScript changes were needed — the click handlers already targeted `.carousel-button` generically and `#product-track` by id, both unchanged.

**Released as:** v1.3.4 (patch — UI/UX repositioning of an existing control, per `VERSIONING.md`).
