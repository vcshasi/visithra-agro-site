2. **Found and fixed a real bug while testing**: submitting the form threw `Uncaught SyntaxError: Invalid regular expression ... /v: Invalid character in character class` from the phone field's `pattern="^[0-9+\-\s()]{7,20}$"`. The browser now compiles HTML `pattern` attributes using the newer Unicode-Sets (`v`) regex mode, which — unlike the older mode this pattern was written under — requires literal `(` and `)` inside a character class to be escaped. Fixed to `pattern="^[0-9+\-\s\(\)]{7,20}$"`, which is valid syntax under both the old and new regex modes, so it's safe regardless of which one a given browser uses.
3. Updated `README.md`'s setup section to reflect that `CONFIG` is now filled in with live values (rather than describing them as placeholders to fill in), and noted that Web3Forms needs no platform-specific setup on either Netlify or Vercel.
